# Requirements

## Functional requirements
1. Create a Firestore-backed database foundation for CreatorAI state and metadata.
2. Provide provider-neutral storage abstractions for source media, derived artifacts, and output files.
3. Define typed domain models for projects, assets, transcript segments, clip candidates, and edit plans.
4. Implement repository and serialization layers for object persistence and validation.
5. Add AI provider interfaces and adapters for transcription and content understanding.
6. Support transcript-first semantic matching with candidate generation and scoring.
7. Support structured EditPlan generation and validation without exposing raw provider commands.
8. Provide deterministic tests for database, storage, and AI behavior.

## Engineering rules
- Source media is immutable.
- AI outputs are validated before use.
- EditPlan is the canonical editable representation.
- Firestore stores metadata/state, not large media bytes.
- Storage paths are generated by application code, never by the AI.
- Client-provided MIME type and file extension are advisory only.
- Long-running work is represented via jobs.
- The AI layer must use adapters behind typed interfaces.

## Non-goals for this phase
- Frontend screen work
- Backend HTTP route changes outside compatibility boundaries
- Full video editor implementation
- Deployment config changes
- FFmpeg rendering logic beyond compatible integration boundaries
